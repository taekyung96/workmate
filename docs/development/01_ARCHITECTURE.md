# 아키텍처

- **결정 근거**: [ADR-0001](../project/adr/0001-spa-bff-session-auth.md) (SPA + BFF + 세션) · [ADR-0005](../project/adr/0005-flyway-migration.md) (Flyway) · [ADR-0006](../project/adr/0006-redis-distributed-state.md) (Redis)

## 1. 구성

```
브라우저 (Vue3 SPA)
   │  HTTP(세션 쿠키) + SSE
workmate-web (:8080) ── 얇은 BFF
   │   • SPA 정적 서빙 — 없는 경로는 index.html 로 넘겨 Vue Router 가 처리
   │   • 세션 인증 (Spring Security · httpOnly 쿠키 · CSRF)
   │   • /api/** → WAS 프록시, /api/**/stream → SSE 중계
   │  REST + 스트림 중계 (내부망) · 사용자 정보는 X-User-Seq / X-User-Role 헤더로 전달
workmate-was (:8081) ── 비즈니스 로직 · JPA/MyBatis · Spring AI
   │
PostgreSQL 17 + pgvector          Redis (세션 · 중복 로그인 · 레이트리밋)
```

| 모듈             | 맡는 일                                                | 맡지 않는 일                                |
| ---------------- | ------------------------------------------------------ | ------------------------------------------- |
| **workmate-vue** | 화면 · 라우팅 · 화면 상태(Pinia)                       | 권한 판정 — 버튼 노출은 안내일 뿐이다       |
| **workmate-web** | 서빙 · 세션 · 프록시 · SSE 중계                        | 비즈니스 로직, DB 접근                      |
| **workmate-was** | 채팅 · RAG · 영수증 · 회의록 · 권한 판정 · 사용량 기록 | 세션 관리 — 브라우저에 직접 노출되지 않는다 |

원칙은 넷이다.

1. **브라우저는 8080 만 본다** — WAS 는 내부망에 둔다. 공격 표면이 하나다
2. **WEB 은 화면을 그리지 않는다** — 중계만 하고 판단하지 않는다
3. **권한은 WAS 가 최종 판정한다** — 프론트와 WEB 을 우회해도 같은 규칙이 적용된다 ([ADR-0003](../project/adr/0003-guide-authz-in-was.md))
4. **3-tier 유지** — 표현(Vue) / 로직(WAS) / 데이터(PostgreSQL)

| 채팅               | Groq Qwen3.8 27B(기본) · Gemini | 화면에서 고른다. 어느 모델이 어느 제공자인지는 `AI_MODEL` 공통코드의 `attr1` 이 정해 재시작 없이 바뀐다 |

Groq 은 OpenAI 호환 엔드포인트라 Spring AI 의 OpenAI 스타터에 주소만 바꿔 붙였다.

RAG 흐름과 파라미터를 정한 근거는 [README](../../README.md#rag-파이프라인)와 [평가 리포트](../features/rag-eval/REPORT-2026-09-04.md)에 있다.

## 3. 인증

- 세션은 **WEB** 이 관리하고 Redis 에 저장한다. WEB 을 여러 대 띄워도 같은 세션으로 인증된다
- 세션 ID 는 httpOnly 쿠키라 스크립트가 읽지 못한다. 대신 CSRF 를 켰다 — SPA 는 `XSRF-TOKEN` 쿠키 값을 `X-XSRF-TOKEN` 헤더로 보낸다
- 인증 실패는 리다이렉트가 아니라 **401 JSON** 으로 응답한다. 화면 이동은 SPA 가 맡는다
- 프론트 `api/client` 는 401 을 받으면 로그인 화면으로 보낸다. 단, 부팅 시 세션 확인(`/auth/me`)의 401 은 정상 흐름이라 제외한다
- 계정 잠금(F1-06)과 중복 로그인 차단(F1-08)은 서버 세션을 즉시 끊는 방식으로 구현했다

## 4. 빌드와 서빙

| 환경 | 방식                                                                                                                                       |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 개발 | Vite dev server(:5173)가 `/api` 를 WEB(:8080)으로 프록시한다. 핫 리로드를 쓰면서 실제 API 를 호출한다                                      |
| 운영 | WEB 의 Gradle `processResources` 단계에서 `npm run build` 를 돌리고 `dist` 를 `static/` 으로 복사한다. WEB jar 하나에 SPA 가 함께 들어간다 |

배포는 GitHub Actions 가 `main` 머지 때 이미지를 GHCR 에 올리고, 서버는 받기만 한다([배포 가이드](11_DEPLOYMENT_GUIDE.md)).

## 5. 데이터

- 스키마는 **Flyway 마이그레이션으로만** 바꾼다. JPA 는 `ddl-auto: validate` 로 대조만 한다 ([ADR-0005](../project/adr/0005-flyway-migration.md))
- 모든 테이블과 컬럼에 `COMMENT ON` 을 단다. 테이블 관계는 [README 의 ERD](../../README.md#db-스키마) 참고
- 이메일·전화번호는 AES-256 으로 암호화해 저장하고, 비밀번호는 BCrypt 로 해시한다

## 6. 에러 처리

| 위치 | 처리                                                                                                                           |
| ---- | ------------------------------------------------------------------------------------------------------------------------------ |
| WAS  | 모든 응답을 `ApiResponse` 로 감싸고, 예외는 `GlobalExceptionHandler` 한 곳에서 변환한다. 컨트롤러마다 try-catch 를 두지 않는다 |
| Vue  | 없는 경로는 라우터의 캐치올(`/:pathMatch(.*)*`)이 404 화면으로, API 실패는 `api/client` 가 공통으로 처리한다                   |
| WEB  | 없는 API 는 404, 없는 화면 경로는 `index.html` 로 넘긴다                                                                       |

번들 로딩 자체가 실패하는 경우(Vue 가 뜨지 못하는 경우)를 위한 별도 정적 에러 페이지는 두지 않았다.
