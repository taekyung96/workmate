# ADR-0001. Vue3 SPA + 얇은 WEB(BFF) + 세션 인증

- **상태**: 채택
- **관련 문서**: [아키텍처](../../development/01_ARCHITECTURE.md)

## 맥락

Workmate 의 중심은 AI 로직(WAS)이다. 채팅 답변을 토큰 단위로 스트리밍하고, 사내 가이드를 검색해 근거를 붙이고,
영수증·회의록을 모델로 분석한다. 이 서버 앞에 무엇을 둘지, 인증을 어떻게 할지를 정해야 했다.

화면 쪽 요구는 이렇다.

- 채팅은 SSE 로 답변이 흘러드는 동안 다른 조작(모델 변경, 방 이동, 도우미 패널)을 해도 상태가 유지돼야 한다
- 영수증·가이드·회의록·관리자 화면을 오가도 로그인 상태와 사이드바가 그대로여야 한다

인증 쪽 요구는 **계정 잠금(F1-06)** 과 **중복 로그인 차단(F1-08)** 이다. 둘 다 서버가 특정 사용자의 로그인을
**그 자리에서 끊을 수 있어야** 한다.

## 결정

1. **프론트는 Vue3 단독 SPA** — Vue Router · Pinia · Vite · TypeScript · Composition API
2. **WEB 은 얇은 BFF** — SPA 정적 서빙, 세션 인증, `/api` 프록시, SSE 중계만 맡는다. 화면을 그리지 않는다
3. **인증은 세션**(httpOnly 쿠키) — JWT 를 쓰지 않는다. WAS 는 내부망에 두고 브라우저는 8080(WEB)만 본다

## 고려한 대안

| 대안                                     | 내용                                                | 기각 이유                                                                                                 |
| ---------------------------------------- | --------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| **A. SPA + 얇은 WEB(BFF)** ✅            | 브라우저 → WEB(세션·프록시) → WAS(내부망)           | —                                                                                                         |
| B. 서버 렌더링(Thymeleaf) + 페이지별 Vue | 화면은 서버가 그리고, 필요한 부분에만 Vue 를 끼운다 | 페이지를 옮길 때마다 상태가 끊긴다. 스트리밍 중인 채팅, 열어 둔 도우미 패널이 이동 한 번에 사라진다       |
| C. 단일 Spring Boot                      | WEB 을 없애고 WAS 가 SPA 서빙과 세션까지 맡는다     | AI 로직 서버에 정적 서빙·보안 설정·세션 관리가 섞인다. 배포 단위도 하나로 묶여 AI 쪽만 따로 늘리기 어렵다 |
| D. SPA 가 WAS 를 직접 호출(JWT)          | WEB 없이 토큰으로 인증                              | WAS 가 외부에 노출된다. 토큰은 만료 전에 회수하기 어려워 F1-06·F1-08 과 맞지 않는다                       |

## 세션을 고른 이유

- 계정 잠금·중복 로그인 차단은 서버가 세션을 **즉시 무효화**하면 끝난다. JWT 는 상태를 서버에 두지 않으니 만료 전 회수에 별도 장치(블랙리스트 등)가 필요하다
- 세션 ID 를 **httpOnly 쿠키**에 두면 스크립트가 읽지 못한다. JWT 를 localStorage 에 두는 흔한 방식보다 XSS 에 강하다
- 대가로 **CSRF 방어**가 필요해진다 → Spring Security CSRF 를 켜고, SPA 는 `XSRF-TOKEN` 쿠키 값을 헤더로 보낸다

## 결과

- 좋은 점: 3-tier(표현 / 로직 / 데이터)가 그대로 유지되고, 공격 표면이 8080 하나로 줄었다
- 좋은 점: 화면 상태가 클라이언트에 있어 스트리밍 채팅과 화면 이동이 서로 간섭하지 않는다
- 대가: WEB 이라는 계층이 하나 더 생겨 요청이 한 번 더 중계된다. SSE 도 WEB 이 받아서 다시 흘려보내야 한다
- 대가: 세션은 서버에 상태가 있으므로 WEB 을 여러 대로 늘리면 공유 저장소가 필요하다 → [ADR-0006](0006-redis-distributed-state.md) 에서 Redis 로 해결했다
